# 报告规范（总监视角）

读者是营销总监、老板或要拿结论开会的人。他们要的是：**这个对手怎么打的、有没有用、我们该怎么办**。数据是证据，不是主角。

## 写作原则

1. **先结论后证据**。封面判词一句话：打法画像 + 最关键的一个数字。例："样本中 73% 的海外内容未识别到合作信号，明确付费合作有 13 条；不能据此判断实际付费规模。"
2. **每条发现都配"所以呢"**。发现是事实，"所以呢"是对我方的含义。没有含义的发现不要放进摘要。
3. **建议动作要能执行**：动词开头，写清优先级（高/中/低）、预算量级（低/中/高）、怎么验证（看什么指标、多久）。
4. **事实和推断分开**。推断写依据（"根据样本里 156/183 条挂车内容推断……"）。
5. **数字带口径**：样本量、时间窗、是中位数还是总数；规模类结论写"下限"；来源冲突两个都写。
6. **标题卖结论，不卖方法**："TikTok 未识别合作信号组的样本播放中位数较高"，而不是"播放量分析"。
7. 用户能认出的词：说"寄样""联盟带货""自来水"，不说"branded_content_type"。
8. **数字要扛得住追问**：每个“X 组比 Y 组好”都写明样本量、合作类型、集中度（见 `audience-research.md` 第 4 节）。没有价格不写“效率”“性价比”。
9. **代表内容链接**：每个竞品附 3–5 条链接，挑高播放的和最能代表它打法的各几条，读者能点开看人家怎么拍。
10. **改数必改文**：数据重抓或口径变了，判词、摘要、各节小结逐句重查，文末保留修订记录（哪一版改了什么、为什么改）。被推翻的结论直接删掉或改写，不要留着再加脚注。

- `style`：`auto`（默认）或 `editorial` / `bento-dark` / `mckinsey` / `swiss` / `xhs-craft`，选择规则见 SKILL.md Step 4。
- `purpose`：报告给谁看、发在哪。`auto` 时按它选风格，写自然语言即可（含"汇报""小红书""社媒""视频"等词）。
- 写标题时考虑风格：`swiss` 和 `xhs-craft` 的标题可以更口语、更有钩子；`mckinsey` 用完整的结论句。
- `actions[].type` 只用：照搬 / 改造 / 避开 / 先小测。
- `summary` 3–5 条；`actions` 3–6 条。
- `weaknesses` 2–5 条，来自你自己读完 `评论摘录.md` 的归纳；没抓评论就省略这个字段，报告显示“未提供 / 待补充证据”，不自动生成痛点。

## 页面结构（build_report.py 固定生成）

封面（标题、判词、样本指标）→ 目录 → 核心卖点与执行摘要 → 差异化与竞品攻防 → 社媒渠道打法 → 价格与价值格局 → 竞品档案 → 真实用户吐槽 → 自然内容实证与建议动作 → 完整证据明细、来源与局限。

- `verdict` 必须是非空字符串，`summary` 与 `actions` 必须是非空数组。生成器不验证叙述结论是否与证据一致，发布前仍须人工核验。
- 可选字段 `pillars`、`battlecards`、`channel_playbook`、`pricing`、`competitors`、`organic_proof` 为对象数组，分别填对应章节。对象字段按原文展示，可用 `title`、`evidence`、`links` 等描述；不要求凑齐固定数量。`channels` 是 `channel_playbook` 的兼容回退。
- 原始 `analysis.json` 的 `plat`、`content_matrix`、`me`、`benchmarks`、`comments` 在相关章节折叠展示；所有字段和 `rows` 原帖链接保留于完整数据附录，不截断样本。`revisions` 可记录修订过程。
- 缺失价格、评论、档案或其他证据显示“未提供 / 待补充证据”。不填入示例产品、假数字或示例结论。封面默认展示实际已有的样本量、博主数、未识别合作信号占比，不自动制造首发价或生态规模。
- `organic` 是未识别合作信号，不等于已确认未付费；播放量与点赞量不能直接比较；没有成本、价格和规格时不计算 ROI 或性价比。
- 单文件 HTML 使用内联 CSS、系统字体和静态正文，断网及禁用 JavaScript 时可阅读。原帖只允许 HTTP(S) 链接，其他字符串按文本展示。数据以安全转义的 JSON 内嵌，便于追溯。
- 五种风格保持相同内容，改变排印、卡片、网格及装饰；默认 `editorial`。旧别名兼容：`brand → editorial`、`terminal → bento-dark`、`consulting → mckinsey`、`wrapped → swiss`、`notebook → xhs-craft`。
- 选择优先级：非 auto 的 CLI → narrative.style → brief.style → purpose → category → editorial。用途优先识别小红书，再识别汇报和社媒；正式交付前仍应让用户确认风格。
- 页面最大宽度 1200px，900px 以下正文单列，窄手机屏幕指标卡也单列。折叠附录应在打印前按需展开。
