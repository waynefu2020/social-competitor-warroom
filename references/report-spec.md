# 报告规范（总监视角）

读者是营销总监、老板或要拿结论开会的人。他们要的是：**这个对手怎么打的、有没有用、我们该怎么办**。数据是证据，不是主角。

## 写作原则

1. **先结论后证据**。封面判词一句话：打法画像 + 最关键的一个数字。例："花知晓是典型的自来水型：73% 的海外内容是用户自发晒单，付费合作只有 13 条。"
2. **每条发现都配"所以呢"**。发现是事实，"所以呢"是对我方的含义。没有含义的发现不要放进摘要。
3. **建议动作要能执行**：动词开头，写清优先级（高/中/低）、预算量级（低/中/高）、怎么验证（看什么指标、多久）。
4. **事实和推断分开**。推断写依据（"根据样本里 156/183 条挂车内容推断……"）。
5. **数字带口径**：样本量、时间窗、是中位数还是总数；规模类结论写"下限"；来源冲突两个都写。
6. **标题卖结论，不卖方法**："TikTok 上自然内容的播放反而最高"，而不是"播放量分析"。
7. 用户能认出的词：说"寄样""联盟带货""自来水"，不说"branded_content_type"。
8. **数字要扛得住追问**：每个“X 组比 Y 组好”都写明样本量、合作类型、集中度（见 `audience-research.md` 第 4 节）。没有价格不写“效率”“性价比”。
9. **代表内容链接**：每个竞品附 3–5 条链接，挑高播放的和最能代表它打法的各几条，读者能点开看人家怎么拍。
10. **改数必改文**：数据重抓或口径变了，判词、摘要、各节小结逐句重查，文末保留修订记录（哪一版改了什么、为什么改）。被推翻的结论直接删掉或改写，不要留着再加脚注。

- `style`：`auto`（默认）或 `consulting` / `wrapped` / `brand` / `terminal` / `notebook`，选择规则见 SKILL.md 第 7 步。
- `purpose`：报告给谁看、发在哪。`auto` 时按它选风格，写自然语言即可（含"汇报""小红书""社媒""视频"等词）。
- 写标题时考虑风格：`wrapped` 和 `notebook` 的标题可以更口语、更有钩子；`consulting` 用完整的结论句。
- `actions[].type` 只用：照搬 / 改造 / 避开 / 先小测。
- `summary` 3–5 条；`actions` 3–6 条。
- `weaknesses` 2–5 条，来自你自己读完 `评论摘录.md` 的归纳；没抓评论就省略这个字段，报告不显示这一节。

## 页面结构（build_report.py 固定生成）

封面（左：判词 + 打法画像；右：内容点阵）→ 4 个关键数字 → 执行摘要（发现 + 所以呢）→ 对标定位 → 内容构成 | 博主量级 → 播放量 → 量级效果 → 主打内容 | 主打卖点 → 内容方向表（有标注时）→ 竞品弱点（有评论时）→ 产品/系列 | 转化渠道 → 官网流量 | 渠道全景 → 建议动作（两栏）→ 案例 → 明细清单 → 口径与局限。

按 PC 端浏览排版（最宽 1200px，"|" 表示并排两栏），900px 以下收成单列。每张图表卡片都有结论式标题和来源行。
